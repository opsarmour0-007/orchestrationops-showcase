# Testing and validation principles

A software change should be evaluated against its **requirements**, not only the absence of runtime errors.

1. **Static checks:** formatting and linting help keep the codebase consistent.
2. **Type checks:** catch incompatible assumptions before runtime when supported.
3. **Unit tests:** check small components and edge conditions.
4. **Integration tests:** verify interfaces between components.
5. **Build checks:** make sure application artifacts can be created.
6. **Human review:** check that acceptance criteria were actually fulfilled.
7. **Clear reporting:** distinguish passed, failed, skipped, and not-run checks.

No specific completion percentage or guaranteed reliability claim is made for the private project.
